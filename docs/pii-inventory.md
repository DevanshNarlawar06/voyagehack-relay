# PII inventory

Generated by `relay docs pii-inventory` from `definitions/skills/*.yaml` and `config/models.yaml` (PRD 14.1). Do not edit by hand. A test fails if this file drifts.

Raw documents and images never leave our infrastructure: OCR is local. Every outbound and inbound payload is stored masked in `model_payloads`, and the console's audit explorer shows the exact text.

## Known gap

**Free-text names and addresses are not masked yet.** Regex and checksum recognizers cover PAN, Aadhaar, IFSC, UAN, mobile, email, date of birth and labelled bank accounts. Names are masked only where a skill already knows them. Named-entity recognition (Presidio) is the planned fix (PRD 27.4). Do not send real personal data to a hosted provider until then.

## Skills

### comms_drafter (v1)

Draft welcome notes, manager briefs and knowledge transfer plans.

- **Fields it can send to a model:** Names, role title, joining or last working date, as filled into a template
- **Masking:** Names are masked as known values, and recognizers cover the rest. Dates and role title are sent as written.
- **When a model is used:** To adjust wording, capped at 150 tokens. The template works without a model.
- **Retention:** Masked payloads are kept in model_payloads with the audit log. The mapping back to real values is in memory for the call only.

### document_extractor (v1)

Extract and validate identity and bank fields from uploaded documents.

- **Fields it can send to a model:** OCR text of a document whose validators failed, which can include name, date of birth, PAN, Aadhaar, account number and IFSC
- **Masking:** Regex and checksum recognizers. **A name on the document is not masked** (see Known gap). Stored output has masked forms plus an encrypted blob, never raw identifiers.
- **When a model is used:** Only when validators fail. Clean documents never reach a model.
- **Retention:** Masked payloads are kept in model_payloads with the audit log. The mapping back to real values is in memory for the call only.

### exception_analyst (v1)

Build the context packet a person sees on a conflict or failure.

- **Fields it can send to a model:** The reason a step stopped, field names, the task's options, and facts passed in by the engine
- **Masking:** Regex and checksum recognizers. Callers should pass facts, not personal data.
- **When a model is used:** To write the summary. The template works without a model, and a suggestion must be one of the task's real options.
- **Retention:** Masked payloads are kept in model_payloads with the audit log. The mapping back to real values is in memory for the call only.

### helpdesk (v1)

Answer policy questions from retrieved text, with citations.

- **Fields it can send to a model:** The question, as typed, and policy passages (not personal)
- **Masking:** Regex and checksum recognizers. **A name typed into a question is not masked** (see Known gap).
- **When a model is used:** Only if a passage clears the similarity floor. Otherwise the question goes to HR with no model call. Without a model, the passage is quoted word for word.
- **Retention:** Masked payloads are kept in model_payloads with the audit log. The mapping back to real values is in memory for the call only.

### intake (v1)

Turn a chat message into an intent and slots.

- **Fields it can send to a model:** The message text, as typed
- **Masking:** Regex and checksum recognizers. **A name typed into a message is not masked** (see Known gap).
- **When a model is used:** Only when the keyword table does not match. Three samples must agree. POSH, grievance and whistleblower messages match the table first, so they never reach a model.
- **Retention:** Masked payloads are kept in model_payloads with the audit log. The mapping back to real values is in memory for the call only.
